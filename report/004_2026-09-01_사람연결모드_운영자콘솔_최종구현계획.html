REPORT #004

사람 연결 모드 + 운영자 콘솔 — 최종 구현 계획

날짜: 2026-09-01 · 프로젝트: AVA (AI Voice Agent for Asterisk) · Report #003을 대체(사람 중심 통화로 요구사항 확정)

결론: AI에게 통화를 맡기지 않는다. 착신 즉시 녹음 그리팅을 재생하고, 사람(운영자) 내선으로 걸어 발신자와 브리지한 뒤, 사람↔발신자 통화 중에 운영자 콘솔(웹 UI)에서 텍스트 TTS 송출·프리셋 음성 클릭 재생으로 음성을 개입시킨다(양쪽 모두 들림). 전부 AVA 쪽(엔진 + Admin UI) 작업이며 Asterisk에는 새로 올릴 것이 없다. 필요한 부품(그리팅 파일 재생, 내선 originate, 사람+발신자 브리지 유지, 브리지 재생, DTMF 이벤트 수신)은 전부 코드에 이미 존재하고, 새로 만드는 것은 "사람 우선 진입 모드"와 "운영자 콘솔" 두 가지다.
확정된 요구사항
  1. 개입 음성은 양쪽(운영자·발신자) 모두 들린다 → 브리지 재생(bridges/{id}/play) 사용
  2. 처음부터 사람이 받는다 — AI는 통화에 참여하지 않음. 최초 그리팅도 녹음 목소리로 재생
  3. 발신자 키패드(DTMF) 입력을 수신해 콘솔에 표시

1. 통화 흐름 (사람 연결 모드)

발신자 착신 → AVA Stasis 진입, 응답(answer) → 믹싱 브리지 생성 (mixing,dtmf_events — 기존 로직) → ① 녹음 그리팅 재생 (greeting_file 재사용, 브리지 재생) → ② 그리팅과 동시에 운영자 내선으로 originate (기존 originate_channel) → 운영자 응답 시 브리지에 추가 → 사람 ↔ 발신자 통화 시작 (AVA는 브리지를 계속 쥐고 있음 — AI 프로바이더는 아예 시작하지 않음) → 통화 중: · 콘솔 텍스트박스 → TTS 합성 → 브리지 재생 (양쪽 들림) · 콘솔 프리셋 버튼 → 등록 음성 즉시 브리지 재생 · 발신자 DTMF → ChannelDtmfReceived → 콘솔 실시간 표시 → 어느 한쪽 종료 시 정리 (기존 세션 정리 로직)

3. 새로 만드는 것

3-1. 사람 우선 진입 모드 (엔진)

  • 설정: config/ai-agent.yaml의 에이전트(또는 DID별)에 mode: operator_bridge + operator.extension(운영자 내선 dial string), operator.ring_timeout, operator.no_answer_action 추가.
  • 엔진 착신 분기: 이 모드면 AI 프로바이더/파이프라인을 시작하지 않고 위 1장의 흐름 실행. 기존 _finalize_predial_transfer_bridge의 브리지 추가·세션 유지 패턴을 재사용하되, "AI 제거" 단계가 필요 없는 단순 버전.
  • 운영자 응답 대기 동안 발신자에게는 그리팅 → (미응답 지속 시) 대기음(MOH) 또는 안내 프리셋 반복.
  • 미응답 폴백(no_answer_action): 안내 후 종료 / 보이스메일 / (옵션) AI 모드로 전환 중 택1 — 기본값은 "안내 후 종료" 권장.

3-2. 운영자 개입 API (엔진)

엔드포인트동작
GET /operator/calls활성 콜 목록(call_id, 발신번호, 상태, 경과시간, DTMF 버퍼)
POST /operator/calls/{id}/say{text, voice} → TTS 합성(wav) → 브리지 재생 (양쪽 들림)
POST /operator/calls/{id}/play{preset_id} → 프리셋 파일 즉시 브리지 재생 (합성 없음 → 지연 최소)
POST /operator/calls/{id}/stop진행 중 개입 재생 중단 (재생 ID로 DELETE)
GET /operator/presets프리셋 목록(id, 라벨, 길이, 전사 텍스트)
  • 재생은 항상 play_media_on_bridge_with_id(결정적 재생 ID)로 → 상태 추적·중단 가능.
  • 동시 개입 요청은 큐잉(직전 재생 종료 후 순차 재생) — 겹침 방지.
  • 보안: Admin UI backend 뒤에서만 접근(기존 내부 인증 준용), 엔진 포트 외부 비노출.

3-3. DTMF 수신 확장 (엔진)

  • src/engine.py:8689 _handle_dtmf_received: 어텐디드 전환 채널이 아닌 발신자 채널 digit → 세션 digit 버퍼 누적 + 콜 이력 기록 + StatusHub push.
  • 브리지가 dtmf_events로 생성되므로 사람 연결 모드에서도 이벤트는 계속 도착.
  • Asterisk 확인 유일 항목: pjsip 엔드포인트 dtmf_mode=rfc4733(또는 auto).

3-4. 프리셋 음성 관리

  • 저장: assets/operator_presets/<lang>/ + 메타데이터(id, 라벨, 파일, 전사, 순서).
  • 등록: (a) 텍스트 입력 → TTS 생성·저장, (b) 음성 파일 업로드(예: 직접 녹음).
  • 최초 그리팅도 같은 체계의 프리셋으로 관리 가능(greeting_file과 일원화 검토).

3-5. 운영자 콘솔 페이지 (Admin UI)

  • admin_ui/backend/api/operator.py: 엔진 API 프록시 + 프리셋 CRUD.
  • admin_ui/frontend/src/pages/OperatorConsolePage.tsx:
    • 좌: 활성 콜 목록(선택) — 발신번호·경과시간·수신 DTMF 실시간 표시
    • 중: 텍스트박스(Enter=송출) + 송출 이력 + 합성/재생 상태 표시
    • 우: 프리셋 버튼 그리드(클릭 즉시 재생) + 재생 중지 버튼
  • 실시간 갱신: StatusHub(SSE)에 operator 컴포넌트 추가 — 콜 시작/종료, 재생 시작/종료, DTMF push.

4. 단계별 로드맵

Phase 1사람 연결 모드 (예상 1–2일)

  • 설정 스키마 + 착신 분기 + 그리팅 재생 + 운영자 originate + 브리지
  • 미응답 폴백(안내 후 종료), 통화 종료 정리
  • 검증: 실제 착신 → 그리팅 → 운영자 전화 울림 → 통화

Phase 2프리셋 클릭 재생 + 콘솔 최소 UI (예상 1–2일)

  • /operator/calls, /play, /stop, /presets + 샘플 프리셋 3개
  • 콘솔 페이지: 콜 목록 + 프리셋 버튼 (SSE 연동)
  • 여기서 "콘솔 → 브리지 재생" 경로 전체 검증

Phase 3텍스트박스 실시간 TTS 송출 (예상 1일)

  • TTS 유틸 공용화 + /say + 텍스트박스·송출 이력 UI
  • 예상 지연: 합성 0.5–1.5초 + 재생 시작 ~0.2초

Phase 4DTMF 표시 + 프리셋 관리 UI (예상 1일)

  • DTMF 핸들러 확장 + 콘솔 실시간 표시
  • 프리셋 생성(TTS)/업로드/삭제 관리 화면

5. 리스크 및 주의사항

  • 중요개입 음성과 대화 겹침: 재생 중 두 사람이 말하면 소리가 섞임(믹싱 브리지 특성). 운영자가 재생 타이밍을 통제하는 운용으로 해결하되, 콘솔에 "재생 중" 표시와 즉시 중지 버튼을 반드시 제공.
  • 운영자 미응답: ring_timeout + 폴백 동작을 Phase 1에서 확정. 발신자를 무한 대기시키지 않는다.
  • 블라인드 전환 금지: dialplan으로 내보내는 _continue_to_dialplan 경로를 타면 채널이 Stasis를 떠나 개입 불가 — 사람 연결 모드에서는 사용하지 않음.
  • 90 운영서버(운영서버) 배포 주의: 운영본. 로컬/스테이징 검증 후 통화 없는 시간대에 엔진 재시작.
  • pjsip dtmf_mode: rfc4733/auto 확인(90 서버·테스트 환경 모두) — inband 전용이면 DTMF 이벤트 미도착.

6. 권장 다음 단계

  1. 운영자 내선 번호(dial string)와 미응답 시 동작(안내 후 종료/보이스메일) 확정
  2. 최초 그리팅 문구·목소리 확정(기존 greeting_file 재사용 여부 포함)
  3. Phase 1 착수 → 로컬 검증 → 90 서버 배포는 별도 일정
