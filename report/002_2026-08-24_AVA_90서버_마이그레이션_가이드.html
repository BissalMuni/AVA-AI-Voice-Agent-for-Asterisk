REPORT #002

AVA 90 서버(Windows) 마이그레이션 가이드
WSL1 Asterisk + WSL2 Docker Engine 구성 (Docker Desktop 불필요)

작성일: 2026-08-24 프로젝트: AVA — AI Voice Agent for Asterisk (v7.5.x) 대상: 90 서버 (Windows, 가상화 사용 가능)
결론 요약

Docker Desktop 없이 배포 가능하다. AVA의 공식 지원 환경은 Docker Desktop이 아니라 Docker Engine + Compose v2이며, 90 서버에는 WSL2 배포판을 하나 추가해 그 안에 Docker Engine을 설치하는 방식(옵션 B)을 권장한다.

Asterisk가 이미 설치된 WSL1 배포판은 그대로 유지한다 — WSL1은 Windows 네트워크 스택을 공유하므로 SIP/RTP 수신에 유리하다. WSL1과 WSL2 배포판은 한 서버에서 공존 가능하다.

현재 오디오 전송이 audio_transport: audiosocket(TCP 8090)이므로 Asterisk(WSL1) → AVA(WSL2) 연결은 Windows의 localhost 자동 포워딩으로 해결된다. UDP 포워딩 문제는 발생하지 않는다.

3. 설치 절차 (권장 경로: WSL2 + Docker Engine)

Step 1 — WSL2 배포판 추가 관리자 PowerShell

기존 Asterisk(WSL1) 배포판은 건드리지 않는다.

wsl --set-default-version 2
wsl --install -d Ubuntu-24.04     # 새 배포판만 WSL2로 설치 (재부팅 필요할 수 있음)
wsl -l -v                          # Asterisk 배포판이 VERSION 1로 유지되는지 확인

Step 2 — Docker Engine 설치 WSL2 Ubuntu 내부

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # 이후 셸 재접속
docker compose version             # Compose v2 확인

최신 WSL은 systemd가 기본 활성화되어 docker 데몬이 자동 시작된다.

Step 3 — 레포 클론 + 설정 이전 WSL2 Ubuntu 내부

반드시 WSL 내부 파일시스템(~/)에 클론한다. /mnt/c/...는 I/O가 느려 음성 처리에 불리하다.

cd ~
git clone <레포 URL> AVA-AI-Voice-Agent-for-Asterisk
cd AVA-AI-Voice-Agent-for-Asterisk
# (미커밋 수정을 패치로 가져온 경우) git apply /mnt/c/.../ava-local.patch
# 2절의 파일들을 동일 경로에 복사 (.env, config/*, data/*)

Step 4 — 접속 정보 수정

항목설정값
.env → ASTERISK_HOST90 서버 LAN IP (예: 192.168.x.90). 컨테이너에서 ARI 접근용
Asterisk http.confbindaddr=0.0.0.0 확인 — 127.0.0.1 단독 바인드면 컨테이너에서 접근 불가
다이얼플랜 AudioSocket 대상127.0.0.1:8090 (localhost 자동 포워딩 이용)

Step 5 — 기동 WSL2 Ubuntu 내부

WSL2 내부는 리눅스이므로 Windows용 오버라이드 파일 없이 기본 compose로 실행한다.

docker compose up -d --build ai_engine admin_ui
docker compose logs -f ai_engine   # 기동 로그 확인

Step 6 — 부팅 자동화 Windows 작업 스케줄러

WSL2 VM은 세션이 없으면 종료되므로, 부팅 시 작업으로 다음을 숨김 실행 등록한다:

wsl.exe -d Ubuntu-24.04 --exec sleep infinity

WSL2가 상시 유지되면 systemd가 docker를 올리고, compose의 restart: unless-stopped 정책이 컨테이너를 자동 복구한다.

4. 검증 체크리스트

✓확인 항목방법
☐Docker 정상 동작WSL2에서 docker ps — ai_engine, admin_ui가 Up 상태
☐ARI 연결 성공docker compose logs ai_engine에서 ARI connected 로그 확인
☐AudioSocket 수신 대기Windows에서 Test-NetConnection 127.0.0.1 -Port 8090 성공
☐Admin UI 접속브라우저에서 http://127.0.0.1:3003
☐실제 통화 테스트내선에서 AI 에이전트 호출 → 인사말 재생 + 양방향 대화 확인
☐재부팅 생존 테스트서버 재부팅 후 위 항목 전체 재확인 (자동화 검증)

5. 대안 경로 (참고): Docker 없이 네이티브 실행

빠른 검증이 우선이면 Asterisk와 같은 WSL1 배포판 안에서 Python으로 직접 실행할 수도 있다. ai_engine의 실체는 python main.py 하나다.

python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python main.py     # 모든 통신이 127.0.0.1 — 포워딩 불필요

장점: 이동 부품 최소, 네트워크 설정 전무. 단점: 공식 지원 경로가 아니어서 업그레이드(agent update)·자동 재시작·Admin UI Docker 관리 기능을 수동으로 관리해야 한다(WSL1은 systemd 없음 → while 루프 스크립트 + 작업 스케줄러). 운영 전환 시에는 옵션 B(3절) 권장. 설정 파일은 양쪽 경로에서 동일하게 사용된다.
