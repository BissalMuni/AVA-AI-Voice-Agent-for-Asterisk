REPORT #001

AVA 한국어 통화 끊김 문제 — 진단 및 해결

날짜 2026-08-24 프로젝트 AVA (AI Voice Agent for Asterisk) 대상 openai_realtime 프로바이더 · 강남구청 당직실 응대 봇

결론 요약

"한글 프롬프트를 쓰면 AI 말이 계속 끊긴다"는 하나의 증상 뒤에 서로 다른 문제 5건이 겹쳐 있었다. 핵심 원인은 오디오 송출 페이서(pacer)의 버그 2건 — ① 미재생 버퍼 조기 폐기, ② 타이밍 드리프트로 인한 재생 중 무음 구멍 — 이며, 에코 오인식·설정 오버라이드 혼선·입력 게인 미설정이 이를 가리고 증폭시켰다. 수정 후 검증 통화에서 인사말 5.1초·답변 14.7초/14.8초가 손실 0으로 전체 재생됨을 로그로 확인했다.

1. 증상

  • 한국어 응대 시 AI 발화가 재생 3~5초 지점에서 잘림. 심할 때는 인사말이 "안녕하..." 0.5초 만에 중단.
  • 재생 중 말이 0.5~1.5초 조각으로 나오고 사이에 1~3.5초 무음 (통화 녹음 파형 분석으로 확인).
  • STT 인식 뭉개짐: "종량제 봉투" → "종양제 봉투", "봉양제 봉퉁". 민원인 측 "전화가 잘 안들립니다".
  • 영어 기본 프롬프트에서는 증상이 나타나지 않아 "한국어 문제"로 오인하기 쉬웠음.

2. 발견된 문제와 대응 (심각도순)

문제 1 · 심각 — 송출 페이서 조기 종료 (뒷부분 통째 손실)

위치: src/providers/openai_realtime.py : _emit_audio_done()

OpenAI는 오디오를 재생 속도보다 2~3배 빨리 생성해 보낸다. 생성 완료(response.done) 신호가 오면 이 함수가 아직 재생되지 않은 버퍼(_outbuf)를 남긴 채 페이서를 즉시 취소했다. 끊기는 시점 = 생성에 걸린 시간이 되므로, 답이 길수록(한국어 존댓말) 잘리는 분량이 커진다. 18:10 통화 실측: OpenAI가 보낸 인사말 약 2.7초 이상 중 0.5초만 재생.

대응: 완료 신호를 올리기 전에 _outbuf가 빌 때까지(최대 60초 가드) 페이서가 실제 오디오를 전부 내보내도록 드레인 대기를 추가. 취소·barge-in 경로는 버퍼를 먼저 비우므로 영향 없음.
문제 2 · 심각 — 페이서 타이밍 드리프트 (재생 중 무음 구멍)

위치: src/providers/openai_realtime.py : _pacer_loop()

20ms 주기 송출을 sleep(0.02) 상대 대기로 구현해 반복당 처리 시간이 누적, 실제 주기가 ~23ms로 밀려 공급 속도가 재생 속도보다 약 14% 느렸다 (로그 drift_pct=-8~-15). 재생 1~1.5초마다 지터 버퍼가 고갈되어 소리가 멈췄다 이어지는 패턴 발생 — 통화 녹음 파형의 "1초 발화 + 1~3초 무음" 반복과 정확히 일치. 네트워크는 핑 1ms 미만·손실 0%로 결백.

대응: 절대시각(monotonic deadline) 스케줄링으로 재작성 — 처리 시간과 무관하게 20ms 주기를 유지하고, 밀리면 대기를 건너뛰어 따라잡으며, 0.5초 이상 정체 시 재동기화. 부하 원인이던 매 20ms PROVIDER CHUNK INFO 로그도 50청크당 1회로 축소 (src/engine.py).
문제 3 · 높음 — 에코/잡음이 발화로 오인되어 재생 플러시

위치: src/engine.py (ProviderBargeIn 처리), openai_realtime.py (speech_started 처리)

설정에서 barge_in.enabled: false로 꺼도 프로바이더 이벤트 경로는 이 플래그를 확인하지 않았다. OpenAI 서버 VAD가 AI 자신의 에코·회선 잡음을 상대 발화로 오인 (입력 트랜스크립트에 "Watch", "Bye", "Oh" 등 무의미 조각으로 기록됨) → speech_started마다 재생 버퍼 플러시·응답 취소 발생. 맞장구가 없는 통화에서도 재현됨.

대응: 반이중(half-duplex) 게이팅 — barge-in 비활성 시 AI가 말하는 동안 (실제 재생 활성 신호 _agent_output_active_calls 기준, 재생 완전 종료 후 600ms까지) 발신자 오디오를 무음으로 치환해 OpenAI에 전송. Google Live에 이미 있던 방식을 확장 적용. 에코가 OpenAI에 도달하지 않으므로 오인식 원천 차단. (초기 버전은 TTS 토큰 기준이라 토큰이 재생 완료 전에 해제되어 실패 → 재생-드레인 신호로 교체)
문제 4 · 중간 — 설정 오버라이드 혼선 (한글 프롬프트 미적용)

위치: config/ai-agent.local.yaml

Admin UI가 관리하는 오버라이드 파일이 instructions를 영어 프롬프트로 덮어쓰고 있어, main YAML에 넣은 한글 프롬프트는 실제로 적용된 적이 없었다. 병합 규칙: 같은 키는 local이 항상 우선, local에 없는 키는 base 적용 — 그래서 greeting(local에 없음)만 한글로 나와 "반은 한글, 반은 영어"인 혼란 상태였음.

대응: 양쪽 파일 모두 강남구청 당직실 한글 프롬프트(+ "한 번에 한두 문장씩 짧게" 규칙)로 통일. 이후 프롬프트 변경은 Admin UI(→ local.yaml) 한 곳에서만 할 것. 엔진 시작 로그의 overridden_keys로 어떤 키가 덮이는지 확인 가능.
문제 5 · 중간 — 인입 음성 게인 미설정 (STT 뭉개짐)

위치: config/ai-agent.yaml : providers.openai_realtime

input_gain_target_rms: 0 / input_gain_max_db: 0으로 입력 정규화가 꺼져 있어, 조용한 전화망 오디오(rms 한 자릿수 관측)가 증폭 없이 OpenAI로 전달 → "종량제→종양제" 수준의 인식 오류.

대응: input_gain_target_rms: 1400, input_gain_max_db: 18 활성화. 아울러 서버 VAD turn_detection.threshold를 0.5 → 0.8로 상향(에코·잡음 오인 감소). 수정 후 "부청장 이름이 뭐야?", "강남 오는 날씨는?" 등 정상 인식 확인.

3. 왜 "한국어만" 끊기는 것처럼 보였나

언어 자체는 원인이 아니었다. 변수는 응답 길이다.

  • 영어 기본 프롬프트: "5~8단어로 답하라" → 응답 1~2초 → 생성 시간 ≈ 재생 시간이라 문제 1(조기 종료)의 손실이 없고, 문제 2(드리프트)의 버퍼 고갈이 일어나기 전에 재생이 끝난다.
  • 한국어 존댓말 응대: 응답 5~15초 → 생성이 재생보다 수 초 먼저 끝나 뒷부분이 잘리고(문제 1), 드리프트 누적으로 중간에 구멍이 뚫리며(문제 2), 에코 노출 시간도 길어진다(문제 3).

※ 실제로 영어 프롬프트가 적용돼 있던 오후 통화들에서도 끊김 이벤트가 로그에 동일하게 기록되어 있었다 — 짧은 응답 덕에 체감되지 않았을 뿐이다.

남은 과제 · 권장 조치

  1. 최종 체감 확인: 20:29 통화 지표는 정상 — 실제 청취에서 멈칫거림이 사라졌는지 확인 후 종결.
  2. 협력자 인스턴스 반영: 코드 수정 2건(문제 1·2·3)과 설정은 협력자 AVA에도 동일 적용해야 같은 품질이 나온다.
  3. 커밋 및 업스트림: 페이서 버그 2건은 업스트림 오픈소스(AVA) 공통 결함으로 판단 — 커밋 정리 후 PR 검토 권장.
  4. 에코 꼬리 미세 조정: 발화 종료 직후 junk 인식("I shamble my")이 남으면 꼬리 보호 600ms → 800ms~1s 연장.
  5. 트레이드오프 인지: 반이중 게이팅 중에는 AI 발화 도중 말을 얹어 끊는 barge-in 불가 (현재 정책과 동일).
