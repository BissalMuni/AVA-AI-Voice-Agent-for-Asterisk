REPORT #003

운영자 콘솔 구현 계획 — 실시간 TTS 송출 + 프리셋 음성 재생

날짜: 2026-09-01 · 프로젝트: AVA (AI Voice Agent for Asterisk) · 대상: src/engine.py, admin_ui, Asterisk(변경 없음)

결론: 세 기능(① 통화 중 키패드 DTMF 수신, ② 텍스트박스 입력 → 실시간 TTS 송출, ③ 프리셋 음성 클릭 재생) 모두 AVA 쪽(AI 엔진 + Admin UI)에 구현한다. Asterisk에는 새로 올릴 것이 없다 — 음성 재생은 기존 ARI 재생 경로(PlaybackManager)를 그대로 재사용하고, DTMF는 이미 엔진에 도착하고 있는 ChannelDtmfReceived 이벤트를 확장 처리하면 된다. Asterisk 쪽 확인 사항은 pjsip 엔드포인트의 dtmf_mode=rfc4733(또는 auto) 하나뿐이다.

1. 왜 AVA 쪽인가

  • 통화가 AVA에 연결된 순간 채널은 Stasis(ARI) 앱 내부에 있다. 이 상태에서는 dialplan의 Read()·Playback() 같은 Asterisk 기능이 개입할 수 없고, 모든 제어(재생·DTMF 수신)는 ARI를 통해 엔진이 한다.
  • 필요한 기반이 이미 코드에 있다:
    • DTMF 이벤트 구독: src/engine.py:782 (ChannelDtmfReceived 핸들러 등록)
    • DTMF 수신 지점: src/engine.py:8689 _handle_dtmf_received — 현재는 어텐디드 전환 상담원 채널만 처리, 발신자 채널 digit은 버림 → 여기를 확장
    • AudioSocket DTMF: src/engine.py:11903 _audiosocket_handle_dtmf — 현재 로그만 남김
    • 음성 재생: src/core/playback_manager.py PlaybackManager — 파일 생성 → ARI 재생, 재생 ID·게이팅·중단 처리 완비
    • TTS 합성: 인사말 파일 기능(greeting_file, OpenAI TTS)에서 이미 텍스트→wav 합성 경로 구현됨 → 재사용
    • UI 기반: admin_ui(FastAPI + React), 실시간 상태 허브 admin_ui/backend/api/live_status.py(SSE StatusHub) 존재

2. 전체 아키텍처

[운영자 브라우저: Admin UI "운영자 콘솔" 페이지] │ ① 텍스트 입력/프리셋 클릭 (HTTP POST) ② 콜 목록·DTMF·재생상태 (SSE 수신) ▼ [Admin UI Backend (FastAPI)] admin_ui/backend/api/operator.py (신규) │ 엔진 제어 API 프록시 (HTTP) ▼ [AI Engine] src/ (신규 operator 제어 엔드포인트) ├─ say: 텍스트 → TTS 합성(wav, media_dir) → PlaybackManager.play → 발신자 채널 ├─ play: 프리셋 ID → 등록된 음성 파일 → PlaybackManager.play → 발신자 채널 ├─ 게이팅: 운영자 음성 재생 중 AI 응답 억제/중단 (ConversationCoordinator 연동) └─ DTMF: _handle_dtmf_received 확장 → 세션에 기록 + StatusHub로 push ▼ [Asterisk] 기존 ARI 재생 경로 그대로 (변경 없음, dtmf_mode=rfc4733 확인만)

3. 구성요소별 작업 내역

3-1. AI 엔진 — 운영자 제어 API (신규)

엔드포인트동작
GET /operator/calls활성 콜 목록(call_id, 발신번호, 상태, 경과시간) — SessionStore에서 조회
POST /operator/calls/{id}/saybody: {text, voice} → TTS 합성 → 발신자 채널에 재생. 재생 전 AI 발화 중단(barge-in 로직 재사용)
POST /operator/calls/{id}/playbody: {preset_id} → 프리셋 파일 즉시 재생 (TTS 합성 없음 → 지연 최소)
POST /operator/calls/{id}/stop진행 중인 운영자 재생 중단
GET /operator/presets프리셋 목록(ID, 라벨, 길이) 반환
  • 인증: Admin UI backend ↔ 엔진 사이 기존 내부 토큰 방식 준용, 외부 직접 노출 금지.
  • 재생 대상: 발신자 채널(또는 브리지). 운영자 재생 중 AI 스트리밍 오디오는 게이팅으로 억제 — OpenAI Realtime 사용 시 response.cancel + 출력 버퍼 클리어(기존 인터럽트 처리 재사용).
  • 대화 컨텍스트 처리: 운영자가 말한 텍스트를 대화 이력에 "assistant(운영자 대리)" 발화로 주입해 AI가 이후 문맥을 이어가게 한다(say는 텍스트가 있으므로 그대로 주입, 프리셋은 등록 시 저장한 전사 텍스트 주입).

3-2. TTS 합성 경로 (재사용)

  • greeting_file 기능에서 구현한 OpenAI TTS(예: alloy) 합성 함수를 공용 유틸로 추출.
  • 합성 결과 wav는 PlaybackManager의 media_dir(/mnt/asterisk_media/ai-generated)에 저장 → 기존 파일 수명 관리에 편승.
  • 예상 지연: 합성 ~0.5–1.5초 + 재생 시작 ~0.2초. 1차 목표로 충분. (스트리밍 TTS 주입은 Phase 4 옵션)

3-3. 프리셋 음성 관리

  • 저장: assets/operator_presets/<lang>/ + 메타데이터(config/ai-agent.yaml의 operator.presets 섹션 또는 별도 json): id, 라벨, 파일, 전사 텍스트, 정렬 순서.
  • 등록 방법 2가지: (a) Admin UI에서 텍스트 입력 → TTS로 생성·저장, (b) 음성 파일 업로드.
  • 예시 프리셋: "잠시만 기다려 주세요", "상담원을 연결해 드리겠습니다", "업무시간 안내" 등.

3-4. Admin UI — "운영자 콘솔" 페이지 (신규)

  • admin_ui/backend/api/operator.py: 엔진 제어 API 프록시 + 프리셋 CRUD.
  • admin_ui/frontend/src/pages/OperatorConsolePage.tsx: 좌측 활성 콜 목록(선택), 중앙 텍스트박스(Enter=송출) + 최근 송출 이력, 우측 프리셋 버튼 그리드(클릭 즉시 재생), 상단 재생 상태/중지 버튼.
  • 실시간 갱신: 기존 live_status.py StatusHub(SSE)에 operator 컴포넌트 채널 추가 — 콜 목록 변동, 재생 시작/종료, DTMF 수신을 push.

3-5. DTMF 수신 (1번째 질문 항목)

  • src/engine.py:8689 _handle_dtmf_received 확장: 어텐디드 전환 채널이 아니면 → 발신자 채널의 digit을 세션 digit 버퍼에 누적 + 콜 이력 기록 + StatusHub push(콘솔에 실시간 표시).
  • 활용처: 운영자 콘솔에 표시(예: 고객이 주민번호 뒷자리 입력), 추후 AI 툴(digit 수집 요청)로 확장 가능.
  • Asterisk 확인 사항(유일): pjsip 엔드포인트 dtmf_mode=rfc4733 또는 auto — inband 전용이면 이벤트가 도착하지 않음.

4. 단계별 로드맵

Phase 1프리셋 음성 클릭 재생 (예상 1–2일)

  • 엔진 /operator/calls, /operator/calls/{id}/play, /operator/presets
  • 프리셋 메타데이터 + 샘플 프리셋 3개(TTS 생성)
  • 콘솔 페이지 최소 버전: 콜 목록 + 프리셋 버튼
  • TTS 합성이 없어 가장 단순 — 재생·게이팅 경로를 여기서 먼저 검증

Phase 2텍스트박스 실시간 TTS 송출 (예상 1–2일)

  • /say 엔드포인트 + greeting_file TTS 유틸 공용화
  • 콘솔 텍스트박스 + 송출 이력, 합성 중 스피너/재생 상태 표시
  • 운영자 발화 텍스트의 대화 컨텍스트 주입

Phase 3DTMF 실시간 표시 + 운영 편의 (예상 1일)

  • _handle_dtmf_received 확장 + SSE push + 콘솔 표시
  • 재생 중지 버튼, 프리셋 관리 UI(생성/업로드/삭제)

Phase 4 (옵션)고급 기능

  • 스트리밍 TTS 주입(ExternalMedia/AudioSocket 경로)으로 지연 0.5초 이하
  • AI 일시정지/재개 토글(운영자 수동 개입 모드), 실시간 전사 뷰

5. 리스크 및 주의사항

  • 중요AI와 운영자 음성 충돌: 운영자 재생 중 AI가 동시에 말하면 겹침. 재생 시작 시 반드시 AI 응답 취소 + 재생 종료까지 신규 응답 억제(기존 barge-in/게이팅 코드 재사용이 핵심).
  • AI가 운영자 음성을 "듣는" 문제: 재생 오디오가 발신자 → AI 입력으로 에코되지는 않지만(ARI 재생은 수신 방향), 발신자가 운영자 음성에 대답하면 AI는 맥락 없이 듣게 됨 → 3-1의 컨텍스트 주입으로 해결.
  • 90 운영서버(운영서버) 배포 주의: 운영본이므로 로컬/스테이징 검증 후 배포. 엔진 재시작이 필요하므로 통화 없는 시간대에 진행.
  • 보안: 운영자 API는 통화에 직접 개입하므로 Admin UI 인증 뒤에만 두고 엔진 포트는 외부 비노출 유지.

6. 권장 다음 단계

  1. Phase 1부터 착수 — 프리셋 재생으로 "엔진 제어 API → PlaybackManager → 발신자" 경로 검증
  2. pjsip dtmf_mode 설정 확인 (90 서버, 테스트 환경 둘 다)
  3. 프리셋 문구 목록 확정 (운영에서 실제로 자주 쓰는 안내 문구 기준)
